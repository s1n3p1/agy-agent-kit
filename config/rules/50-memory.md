# Durable Memory

Load when a significant system/service/project decision should be remembered beyond the current session.

- Reuse an existing durable memory or project documentation system when one already exists instead of creating a second parallel system.
- Do not create project-local `.agents/`, `.gemini/`, or harness directories merely to store routine history.
- Persist only information that will materially affect future work: architecture decisions, service mappings, operational constraints, durable configuration changes, unresolved TODOs, and verification evidence worth carrying forward.
- Do not store secrets, credentials, or full chat transcripts.
- If no durable memory system exists, prefer concise repository documentation over inventing a complex memory framework.
